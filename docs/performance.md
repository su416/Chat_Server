# ChatServer 轻量性能测试记录

## 1. 测试目标

对 ChatServer 的核心链路做一版轻量压力测试，验证项目在本地环境下的基本吞吐、稳定性与主要瓶颈。

---

## 2. 测试环境

- OS: Ubuntu 24.04
- Compiler: g++ 13.3.0
- CMake: 3.x
- MySQL: 8.x
- Redis: 7.x
- Server IP: 127.0.0.1
- Server Port: 6000
- Server Thread Num: 4
- Client: 命令行客户端 / Qt 客户端 / 压测脚本
- Network: 本机回环地址

---

## 3. 测试链路

### 3.1 登录
验证登录请求的基础处理能力。

### 3.2 单聊发送
验证单聊消息转发、离线存储、聊天记录落库链路。

### 3.3 群聊发送
验证群聊广播、Redis 转发、离线消息与历史消息落库链路。

---

## 4. 记录指标

- 并发数

- 总耗时
- 平均耗时
- 服务端 CPU 占用

## 7. 初步结论

- 登录链路整体较轻，主要消耗在用户查询与状态更新
- 单聊链路除网络收发外，还涉及聊天记录落库和离线消息处理
- 群聊链路开销明显高于单聊，主要原因是需要遍历群成员并执行多次转发 / Redis 发布 / 离线消息写入
- 当前项目更适合作为功能完整、结构清晰的中小规模聊天系统示例，后续可继续优化数据库访问方式、锁粒度和协议序列化

---

## 8. 后续优化方向

- 将高频 SQL 链路逐步替换为 prepared statement
- 引入数据库连接池
- 优化群聊链路中的锁范围
- 补充更系统的压测脚本
- 对 JSON 与 Protobuf 序列化开销进行对比


在单聊轻量压测中，10 个并发 worker 中有 9 个成功完成登录并发送消息。成功 worker 共发送 180 条消息，数据库中的 chatmessage 与 offlinemessage 记录数均为 180，说明 null-terminated 分帧方案已能正确支撑成功连接上的消息边界处理。当前剩余问题主要表现为个别 worker 在登录或响应等待阶段超时，后续将继续通过放宽超时和细化脚本日志进行定位。

### 6. 运行观察

- 本轮测试中，10 个并发 worker 均成功完成注册、登录与消息发送。
- 数据库中 `chatmessage` 与 `offlinemessage` 记录数均为 200，与请求消息数完全一致。
- 说明基于 `\0` 分隔符的 TCP 消息边界方案已经能够正确支撑单聊链路的轻量压测。
- 当前单聊链路已从“功能正确”提升到“功能 + 分帧 + 轻量压测验证正确”。
